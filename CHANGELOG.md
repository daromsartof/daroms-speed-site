# Changelog

All notable changes to daroms-speed-site. Versions follow `VERSION`.

## 0.1.0 (unreleased)

- Repository skeleton: pnpm workspace, `@dss/config` (strict TypeScript base with type-stripping-safe flags,
  shared flat ESLint config for core and sites, Prettier), Vitest, CI.
- Golden site template (Next 16.4.6, React 19.3, Tailwind v4 with explicit sources, typed routes, static CSP and
  security headers, copy in `content/`, generated `fonts.ts`/`theme.css`/`theme.ts` placeholders, exact Next
  `AGENTS.md` block). Verified: all routes static, OpenNext Cloudflare build + `wrangler deploy --dry-run`
  (static-assets incremental cache, ~1 MiB gzip worker), local workerd serving headers, Docker standalone image,
  `core/` attached as a git submodule, `cacheComponents` on and off.
- Core packages (TypeScript sources, Node-safe subpaths for config-time imports):
  - `@dss/design`: Design DNA schema, 14 archetypes, 42 curated font pairings validated against next/font data,
    OKLCH palettes with WCAG minimums enforced by construction (ink 7:1, muted/accent text 4.5:1), deterministic
    roller scoring industry/mood fit and penalising resemblance to recent sites and the generic indigo/violet band,
    generators for `theme.css` (Tailwind v4 tokens, type scale, radius, density, motion, textures), `fonts.ts`,
    `theme.ts` and a monogram `icon.svg`.
  - `@dss/security`: static CSP builder with presets (Turnstile, Plausible, Umami, Cloudflare Analytics, YouTube,
    Vimeo, Cal.com, Maps, Stripe), security headers, `safeAction` (honeypot, rate limit per IP, Turnstile, zod,
    sanitised errors), lazy env validation, rate limiters (memory, Workers binding), client IP.
  - `@dss/site`: `defineManifest` (zod, readable errors) and `withDss` (headers, CSP from manifest and modules,
    images, redirects, trailing slash, standalone output for Docker, refuses nonce CSP with cacheComponents).
  - `@dss/seo`: root and page metadata (canonical, hreflang + x-default, noindex on previews), JSON-LD builders
    with a `<`-escaped graph, robots (AI training crawler policy), sitemap, llms.txt.
  - `@dss/ui`: token-driven primitives (Container, Section, Stack, Cluster, Grid, Heading, Text, Eyebrow, Prose,
    Button, ButtonLink, Media, SkipLink, VisuallyHidden, Accordion on Radix).
  - `@dss/data`: Drizzle on SQLite (D1 binding, libSQL), id/timestamp columns, drizzle-kit config per driver.
- Template now uses the manifest, the DNA and the packages. Golden page: Lighthouse mobile 96 performance,
  100 accessibility, 100 best practices, 100 SEO; OpenNext build green.
- `dss` CLI (TypeScript run by Node in a site, esbuild bundle for npm): `new` (template copy, core as submodule pinned
  to the creating commit, `--copy` snapshot or `--link`, install, DNA roll with history, preset pages), `dna roll|show`,
  `theme`, `g page|section`, `add list|section`, `doctor` (manifest, theme freshness, pages, placeholders, types, lint),
  `dev`. Verified: vitrine and landing presets build fully static in submodule, copy, link and npm-installed modes.
- Section registry (10 sections: hero, features, services, story, testimonials, cta, faq, contact, stats, steps) with
  version stamps, JSON placeholder copy and archetype fit; presets `vitrine`, `landing`, `blank`; site chrome (header
  with no-JS mobile menu, footer, skip link) and placeholder images flagged by `dss doctor`.
- AI layer (`_ai/`, synced into each site's `.claude/` on SessionStart): 61-line kernel with verified Next.js 16 facts,
  15 path-scoped rules and 11 on-demand rules with a generated one-line digest, 20 `dss-*` skills (orchestrator
  `/dss-site`, forked Sonnet/Haiku workers for copy, pages, sections, SEO, checks, polish, learn, commit), 5 agents with
  output contracts (critic, designer, reviewer, SEO auditor, a11y), 11 vendored third-party skills loaded name-only with
  licenses and provenance, and Python hooks: sync, prompt router (pages and sections of the site, French aliases, silent
  when unsure), rule gate (DNA tokens, default Tailwind palette, Next 16 APIs, secrets, JSX copy, slop gate on content),
  per-file typecheck and lint, secret-file deny, session stats with context warning.
- `core/CATALOG.md` generated by `dss catalog` (tokens, primitives, registry sections, archetypes, font pairs, package
  APIs), kept fresh by a test; `dss sync-ai`; `dss cost` writes `site.cost.md` (per step, model, session).
- Verified live with Claude Code headless in a generated site: a non-compliant write was refused by the hook and reported
  verbatim; `/dss-copy home` (forked Sonnet) replaced placeholders with brief facts, kept unknown testimonials as open
  facts, doctor and build stayed green; `dss cost` reported the sessions.
- `@dss/motion`: scroll reveals, stagger, parallax, marquee and split words in pure CSS (`animation-timeline: view()`),
  disabled for reduced motion and DNA motion `none`; client `CountUp`.
- `@dss/three`: `<Scene>` loads three.js and the scene only near the viewport and when the main thread is idle, pauses
  offscreen, keeps a server-rendered poster on phones, data saver, reduced motion, no WebGL or DNA three `none`.
  Registry scenes `gradient` (shader in DNA colors) and `particles`; `dss add scene`; adding @dss/three also adds
  `three`/`@react-three/fiber` to the site.
- Registry grows to 21 variants (hero: split-editorial, scene, kinetic, fullbleed-image, mono-index; features: numbered,
  bento; logos, gallery, projects, team, pricing, manifesto); variant picked per site with the DNA seed among the ones
  fitting the archetype, 3D variants skipped when DNA three is `none`; `portfolio` preset.
- Verified: 5 briefs produced 5 archetypes (minimum pairwise DNA distance 0.70), all static, rule gate clean, types and
  lint green; the 3D site scores Lighthouse mobile 100 performance (LCP 0.8 s, TBT 70 ms) and desktop 100.
- Modules (`dss module add|remove|list`, also `dss new --modules` and per-preset defaults): site-owned files, npm
  dependencies, `.env.example` documentation, CSP presets (config-driven for analytics), manifest pages and nav labels,
  a section appended to a page, and generated slots (`lib/modules.ts` for sitemap and llms.txt entries,
  `components/site/module-slots.tsx` for end-of-body scripts). Removal deletes unmodified files and empty folders and
  keeps presets other modules need. v1 modules: `forms` (Server Action via safeAction, Resend REST, Turnstile, accessible
  form), `legal` (legal notice and privacy pages, GDPR and nLPD structure, footer links), `analytics` (Plausible, Umami or
  Cloudflare, production only), `blog` (Markdown articles, Article JSON-LD, RSS, sitemap and llms.txt entries).
- `dss db init --driver d1|libsql|postgres`: @dss/data and Drizzle in the site, schema, client, drizzle.config.ts,
  D1 binding in wrangler.jsonc, env docs, `db:generate`, `db:migrate`, `db:studio`; Postgres client and pg columns;
  Cloudflare bindings available in `next dev` for D1 sites.
- `dss new` names the Worker and the Docker image after the site.
- Verified: a vitrine site with forms, legal, analytics and blog builds static/SSG; footer legal links, form fields,
  sitemap and llms.txt entries, CSP presets and the analytics script are served; the form returns field errors from the
  server and a generic failure without email credentials (real browser); removing blog and analytics rebuilds green;
  libSQL and local D1 migrations apply.
- AimKit 0.3.0 vendored in `packages/aimkit` (bridge, MCP server, Chrome extension; `scripts/vendor-aimkit.mjs`,
  provenance in VENDOR.md). Upstream in domtake (branch `feat/english-default`): bridge CLI, MCP descriptions and
  instructions, skill text and messages in English; `context.md` always written in English for the agent while the
  extension UI keeps its language; unit tests and e2e expectations updated.
- Sites: `@dss/aimkit` in the workspace, `.aimkit.json`, `aimkit` MCP entry; `dss dev` runs the bridge next to `next dev`
  (`--no-aimkit` to skip); `dss aimkit setup|token|init`; `/dss-edit` reads the context labels directly.
- `dss mcp list|add|remove` with verified opt-in recipes: MotionSites (OAuth), 60fps (licence, iOS motion references),
  Context7, Playwright MCP, gbrain.
- Verified: in a generated site, `dss dev` serves Next and starts the bridge on 7457 (unsigned requests refused); the
  aimkit MCP server answers `tools/list` and returns the latest context (request and exact source line) in English.
- Factory brain (`~/.dss/brain`, Karpathy LLM wiki with gbrain-style pages): `dss brain init|query|status|log`, schema,
  index-first retrieval with stem matching, skills `/dss-brain-query` (Haiku), `/dss-brain-ingest` (Sonnet, privacy
  rules), `/dss-brain-lint`; the prompt router adds a one-line brain hint; access through `additionalDirectories`.
- `dss sites` registry (`~/.dss/sites.json`, recorded by `dss new` and `dss deploy`); `dss deploy` (Cloudflare upload or
  deploy, Vercel, Docker) with noindexed previews and production gated by `doctor --strict` and a real domain;
  `/dss-handoff`; site workflows `ci.yml` (submodules, doctor, lint, types, build) and opt-in Cloudflare `deploy.yml`.
- Verified: a Docker preview built by the deploy flow serves `Disallow: /` and `noindex`; Claude Code (headless, Sonnet,
  $0.19) ingested a site into a scratch brain (site, industry and voice pages, indexed, no orphan) and a second site's
  `dss brain query` returned them.
- Release and production tooling: `publish.yml` (tag = VERSION = package.json, npm trusted publishing or NPM_TOKEN),
  `dss release-core` (versions, changelog section, commit, tag), `dss upgrade` in sites (core to the latest tag,
  template dependency versions aligned, AI layer and theme refreshed, doctor), `dss factory run` (one site per brief,
  optional headless `/dss-site --auto`, `factory.log.jsonl`).
- Docs: nine pages in `docs/`, CLI reference, `llms.txt` and `llms-full.txt` generated by `dss docs` and kept fresh and
  link-checked by tests; README rewritten.
- Verified: `npm publish --dry-run` (675 kB, 556 files, AimKit build and docs included, no tests); a vitrine site created
  from the packed tarball builds static with forms and legal, passes doctor, takes a 3D scene, and type-checks all 26
  registry sections and both scenes.
- GitHub Actions on Node 24 (framework and site templates): checkout v7, setup-node v7, setup-python v7,
  pnpm/action-setup v6; checkouts drop persisted credentials, and the publish and deploy jobs run without a dependency
  cache.
- `dss factory run --agent` passes the site's permission rules to headless Claude Code (untrusted folders ignore project
  `permissions.allow`, which blocked every `pnpm dss` command) and adds the brain directory.
- Found by the first full agent demo (Clear to Board): sites get `pnpm test` (Node's built-in runner, no dependency,
  run in site CI and by /dss-check) with a `dss-tests` rule; site permissions allow the local checks /dss-check needs
  (`pnpm start`, Lighthouse, `curl` on localhost, `pnpm cf:build`, wrangler dry run); the `any` rule ignores string
  literals (copy like "Fake sites: any payment" was refused); `factory run` reports a run stopped by an error, max
  turns or a usage limit instead of "ready", and allows WebFetch so headless research can open competitor sites.
- `dss deploy` (Cloudflare preview) creates the Worker on the first preview: wrangler refuses `versions upload` before
  a first deploy. Found on the first real deploy (Clear to Board preview on workers.dev, noindex verified).
- Studio credit on every site: the template footer links to https://daromsart.xyz/ ("Site by Daroms'Art", from
  `content/site.ts > footer.credit`), the kernel tells agents to keep it, and `dss doctor` checks it (warning, error with
  `--strict`, so production deploys need it).
